# Workshop: from request to tested skill

## Agenda (90 minutes)

1. 0–10: purpose, invented-data rule, and boundaries.
2. 10–25: map one task using `requirements/request-template.md`.
3. 25–45: write a skill with instructions, examples, and escalation rules.
4. 45–60: create a normal, edge, and blocked evaluation case.
5. 60–75: try the skill in the UI and inspect feedback and audit records.
6. 75–85: review the scorecard and revise the skill.
7. 85–90: decide owner, version, and next review date.

## Markdown slides

### 1 — Why a small platform?
Reusable patterns, visible boundaries, and measured iteration for low-risk experiments.

### 2 — Start with the work
Name the user, task, friction, approved context, and outcome before choosing an AI feature.

### 3 — Write the skill
Instructions + examples + boundaries + escalation. Keep it reviewable and versioned.

### 4 — Test before reuse
Use invented examples, score observable criteria, and include inputs that should be blocked.

### 5 — Keep a human in control
Drafts are not actions. Review outputs and record feedback; never use real data in this lab.
